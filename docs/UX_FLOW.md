# 使用者流程

## 主要流程

```text
首次使用：登入 → 資料使用 → 排課偏好 → 課程興趣探索 → 儀表板與首份課表
再次使用：登入 → 儀表板 → 個人資料設定、課表比較、儲存課表或畢業學分檢查
```

## 路由

| Route | 頁面 | 說明 |
| --- | --- | --- |
| `/login` | LoginPage | 登入 |
| `/onboarding` | OnboardingPage | 首次導覽的資料使用確認 |
| `/setup` | SetupPage | 初始偏好設定 |
| `/interest-exploration` | InterestExplorationPage | 排課前的課程興趣探索 |
| `/` | DashboardPage | 儀表板與主要排課 |
| `/schedule` | SchedulePage | 課程瀏覽、手動選課與 AI 對話排課 |
| `/search` | SearchPage | 課程搜尋 |
| `/graduation` | GraduationPage | 畢業學分檢查 |

## 登入流程

1. 使用者輸入學號與密碼。
2. 前端呼叫 `/api/auth/login`。
3. 登入成功後，使用者資料寫入 `localStorage`。
4. 若尚未完成設定，導向 `/onboarding` 或 `/setup`。
5. 若已完成設定，導向 `/`。

## 初始偏好設定流程

1. 確認必要的資料用途。個人化學習、協同推薦與研究同意各自選擇，協同推薦須先開啟個人化學習。
2. 首次設定依序確認基本資料、選課程興趣、選排課條件。在課程興趣步驟可先回答細項，或繼續時一次確認未回答的類別。返回上一步會保留本次表單答案。
3. 呼叫 `POST /api/profile` 保存偏好。首次設定完成後進入興趣探索，此時還沒有發出排課請求。
4. 探索卡可以回饋、略過單張，或結束探索並前往課表。完成或略過後，首頁依已保存的偏好與可用的回饋產生首份課表。同一瀏覽器可從偏好設定續做未完成的探索，也可主動重新開始。
5. 已設定過的使用者可直接選擇要修改的設定區塊，保存時會更新課表。若正在探索，則回到探索續做。

## 課程搜尋流程

1. 使用者輸入關鍵字或條件。
2. 前端呼叫 `/api/courses`。
3. 顯示課程列表。
4. 使用者可查看課程詳情。
5. 未來應支援將課程標記為 `關注` 或 `加選`。

## 推薦課表流程

1. 使用者在儀表板設定偏好。
2. 前端呼叫 `/api/schedule/generate`。
3. 後端根據偏好與課程資料產生課表。
4. 前端顯示課表格、總學分與推薦訊息。
5. **課表上方出現確認列「這份課表符合你的需求嗎？」**（Roadmap #2）。
   - `[符合]` → 記錄為接受這份推薦，確認列改為已記錄的說明。
   - `[需要調整]` → 提示使用者點選不適合的課，走下方的移除原因流程。
   - 排課只是推薦，使用者是否覺得符合需求才是最終選擇；沒有回答就是沒有接受，不代為假設。
   - 未同意「從互動持續改善個人化」時確認列仍會顯示，只是不產生任何記錄。
6. 未來應顯示多方案比較。

## 關注與加選流程

### 關注

- 使用者將課程加入關注。
- 課程顯示於課表預覽。
- 不列入衝堂。
- 可同時關注多門同時段課程。

### 加選

- 使用者將課程加入正式課表。
- 課程佔用時段。
- 若與其他加選課衝突，需提示衝堂。

### 移除（退選）

- 從課表移除課程時，先詢問原因：時間衝突／課程內容／授課教師／課業負擔／人數已滿／
  不符資格／其他，另可「略過」。
- 為什麼要問：時間衝突、額滿與不符資格對「課程內容偏好」是**中性**訊號，只有內容、
  負擔、教師才是真正的負回饋。不問就分不出「排不進去」與「不喜歡」。
- 略過時記為「沒有說明」，不猜測理由。
- **未同意「從互動持續改善個人化」時不顯示這個對話框**，直接移除——問了也不會記錄。

## AI Agent 流程

1. 使用者輸入自然語言需求。
2. Agent 判斷意圖。
3. Agent 呼叫課程查詢、評價查詢、偏好更新或排課工具。
4. Agent 根據工具結果回覆。
5. 若產生課表，前端更新課表顯示。
6. **Agent 必須接著詢問這份課表是否符合需求**，並說明若有不適合的課請指出哪一門及原因。
   使用者回答後，Agent 先呼叫 `record_schedule_feedback` 記錄，再回覆（Roadmap #2）。

## 畢業學分檢查流程

1. 使用者進入 `/graduation`。
2. 前端呼叫 `/api/graduation/:studentId`。
3. 顯示總學分、分類學分、缺口與推薦。
4. 使用者可依缺口返回排課。
