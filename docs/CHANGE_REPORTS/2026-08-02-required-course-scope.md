## 問題

`Courses.type = '必修'` 代表「**某個班級**的必修」，不是「**這位學生**的必修」。`scheduler.js` 以 `course.category === '必修'` 判定必修，因此全校 2094 筆必修 section 全部被當成每位學生的必修，課表橫跨 79 個系所並含 12 個不同研究所的碩士論文。

判定依據只有 `course.department`，而它實際上是**班級名稱**（`資訊三甲`），不是系所名稱（`資訊工程學系`）。

## 主要改動內容

### 系所對照（`server/src/data/departmentMapping.js`）

以 `docs/DEPARTMENT_MAPPING.md` A 表為唯一真相來源（使用者核對完畢）：**71 個簡稱對應 69 個系所**。其中兩組是多簡稱同系所，必須以「系所 → 簡稱清單」表達而非一對一：

| 系所 | 簡稱 |
| --- | --- |
| 機械與電腦輔助工程學系 | `機電`（大學部）、`機械`（碩士班） |
| 室內設計進修學士班 | `室內設計`、`室設` |

### 班級名稱解析（`server/src/skills/courseScope.js`）

`parseClassName()` 把班級名稱解析為「系所簡稱 + 學制 + 年級」。兩個關鍵設計：

**1. 最長簡稱前綴。** `資訊` 與 `資訊電機`、`商學` 與 `商學進修`、`建築` 與 `建築專業` 前綴重疊，必須先試長的。

**2. 簡稱後必須緊接「（學制）+ 年級字」。** 單純比對前綴會產生大量假陽性，實跑 562 個真實班級名稱抓到：

| 班級名稱 | 只比對前綴的誤判 | 正確判定 |
| --- | --- | --- |
| `建設英班` | 建設碩士在職學位學程 | 英語授課班 |
| `商學院綜合班` | 商學（剩下「院綜合班」） | 學院綜合班 |
| `金融學院碩士綜合班` | 金融博士學位學程 | 學院綜合班 |
| `資通安全學程` | 資訊安全碩士學位學程 | 學分學程 |
| `人工智慧探索應用學分學程` | 人工智慧技術與應用學士學位學程 | 學分學程 |
| `商學一(UQ)` | 商學博士學位學程一年級 | 國際學程 |

`商學一(UQ)` 這筆說明順序也重要：它**確實**符合「簡稱 + 年級」樣態，因此國際學程與英語授課班的判定必須排在系所解析**之前**。反過來 `學程$` 不能排在前面，否則 `建築二學位學程`、`國企一學位學程` 這些真正的系所班級會被誤判。

學制標記 `碩專` 必須先於 `碩` 比對，否則 `智能工程碩專一學位學程` 會被判成碩士班一年級。

### 排課引擎（`scheduler.js`）

| 課程 | 處理 |
| --- | --- |
| 本系所本學制本年級的必修 | 必修階段優先排入 |
| 同系所其他年級／其他學制的必修 | **整批排除，不進候選** |
| 其他系所的必修 | **整批排除，不進候選** |
| B～F 類（通識、共同、學院綜合班、英語班、學分學程）的必修 | 保留為候選，**但不享有必修優先度** |

**為什麼是排除而不是降低優先度**：學生根本無法修習他系必修，降低優先度只會讓它們在選修填充階段被撿回來。

**為什麼非本人必修要拿掉必修優先度**：第一版只做了「不強制排入」，實測課表仍出現 `商創一(RMIT)｜管理學`、`未完成課程(大學)｜商業應用統計`——它們透過 `CATEGORY_PRIORITY['必修'] = 0` 在貪婪填充階段壓過本系選修。這類課程仍保留為候選（適用對象規則未定），但不應優先。

**學生範圍無法判定時**（缺系所或年級）不得退回「全校必修都算」，那正是本缺陷本身；改為不把任何課當成必修並發出警告。此時也**不**降低必修優先度——範圍不明時沒有更好的訊號，維持既有排序，避免未帶 profile 的呼叫端結果無聲變差。

### 限制條件與前端

- `constraintService.js`：把 `department` 與 `gradeLevel` 帶進排課限制。先前兩者從未進入排課引擎，引擎無從判定範圍。
- `SetupPage.jsx`：年級預設值由固定 `'1'` 改為登入使用者的實際年級。原本三年級學生走完設定流程會被存成大一，拿到的是大一必修——這個缺陷在必修範圍收斂後才會顯現。

### 資料檔對齊

`users.json` 與 `user_preferences.json` 的資料先前對不起來：

| 檔案 | 內容 | 問題 |
| --- | --- | --- |
| `users.json` | `D1249697` 資訊工程學系 **3 年級** | 唯一真實使用者 |
| `user_preferences.json` | `D1249697` 資訊工程學系 **1 年級** | 年級與 `users.json` 衝突 |
| `user_preferences.json` | `D1249196` 電機工程學系 2 年級 | `users.json` 中無此使用者 |
| `user_preferences.json` | `default` | 模擬資料產生器建立的預設偏好 |
| MySQL `User_Profiles` | `user_id=1` 資訊工程學系 `grade_level=3` | 與 `users.json` 一致 |

依「以 `users.json` 為準」整併為單一筆 `D1249697`（資訊工程學系、3 年級），並清掉指向模擬課程的 `completedCourseIds`。

模擬課程資料（`courses.json` 55 筆、`reviews.json` 167 則）與其產生器 `seed.js` 一併刪除，`npm run seed` 指令同步移除。保留 `seed.js` 等於留著一個指令就能把剛清掉的模擬資料再灌回來，而且它會連帶清空 `user_preferences.json`。課程與評價一律來自 MySQL。

## 影響範圍

- `POST /api/schedule/generate` 與 AI Agent 排課工具的必修判定。
- **行為變更**：先前每位學生都會拿到全校 2094 筆必修，現在只拿到本系本年級的必修。這正是修復目的。
- `npm run seed` 已移除；沒有 MySQL 連線時後端會退回本機 JSON，但課程與評價集合為空。
