# UI／UX 全面檢查：導覽列統一、方案切換與說明恢復、移除方案比較與橘色通知

- 日期：2026-10-26
- 起因：使用者要求檢查所有畫面與資料流是否矛盾。例如返回箭頭、畢業學分頁仍指向已移除的排課頁，選單也缺少「隱私與資料」。
  使用者也擔心 PR #27（前端介面大幅瘦身）刪掉了先前做的功能。另外要求不論排出幾個方案都顯示方案選擇與方案說明。
- 檢查中使用者追加的要求：
  - 移除課程對話框刪掉「不提供原因」，且不得預設勾選。
  - 方案說明要可收合。
  - 刪除方案比較。
  - 刪除方案上方的橘色通知。
  - 每個帳號都要在瀏覽器跑過。

## 發現的問題

| # | 問題 | 來源 |
| --- | --- | --- |
| 1 | 首頁、尋找課程、探索、畢業學分頁各自複製一份頂部導覽列，內容不一致。畢業學分頁有指向已刪除 `/schedule` 的「排課」按鈕；尋找課程、探索、畢業學分頁的選單沒有「隱私與資料」 | PR #27 刪除 SchedulePage 時沒有同步各頁導覽列 |
| 2 | 設定頁返回箭頭固定回 `/onboarding`，已設定過的使用者按了會回到引導流程 | 同上 |
| 3 | 興趣卡面頁完成或跳過後 `navigate('/schedule')`。該路由已不存在，最後只能靠萬用路由轉回首頁 | 同上 |
| 4 | 只排出 1 個方案時整個方案列隱藏，使用者看不出系統嘗試了幾種取向、為什麼只剩一個 | PR #27 |
| 5 | 方案說明與「其他取向為什麼沒產生」的原因被拿掉 | PR #27 |
| 6 | 移除課程對話框預設勾選「不提供原因」 | 既有行為 |
| 7 | `ScheduleNotice` 被改成 `return null`，連排課失敗的錯誤訊息都不會顯示 | PR #27 |

PR #27 移除的「修課路徑」「課程主題」選項與「重新探索課程主題」按鈕，已在同日前一個提交恢復（見〈設定頁恢復…〉報告）。
本次逐一比對 PR #27 的刪除內容，其餘刪除沒有發現造成功能缺口。

另有兩點既有狀況，本次不動：

- 首頁的課程詳情不顯示時間地點（`showTime={false}`）。這在 PR #27 之前就是如此。
- 前端 `scheduleAPI.counterfactual()` 與後端 `/api/schedule/counterfactual` 仍在，但前端已無呼叫端（原本只有方案比較面板使用）。

## 修改

- **新增 `client/src/components/Layout/TopNav.jsx`**：共用頂部導覽列。
  - 連結：首頁／尋找課程／探索。
  - 使用者選單：個人資料設定、畢業學分進度、隱私與資料、切換主題、登出。
  - `DashboardPage`、`SearchPage`、`ExplorePage`、`GraduationPage` 改用此元件，刪除各自重複的選單狀態與程式碼。畢業學分頁的「排課」按鈕隨之消失。
- **`SetupPage.jsx`**：返回箭頭在已完成設定時回首頁（提示「返回首頁」），未完成時才回引導流程（「返回上一步」）。
- **`InterestExplorationPage.jsx`**：完成、跳過、讀取失敗時的 3 處 `/schedule` 改為 `/`。
- **`PlanSwitcher.jsx`（改寫）**：
  - 只要有方案就顯示方案按鈕，1 個也顯示。每個按鈕標出門數與學分，系統主推的方案有星號圖示。
  - 下方「方案說明」可收合，收合狀態記在瀏覽器（`fcu_plan_explanation_open`，預設展開）。
  - 說明內容為所選方案的取向描述。若有取向沒排出不同課表，會寫「這次只產生 1 個方案：系統嘗試了 4 種取向，其他 3 種…」或「另有 N 種…」。
  - 「為什麼？」可展開，逐一列出每種取向沒產生的原因，文案與後端 `COLLAPSE_REASON_TEXT` 對齊。
- **刪除 `PlanComparison.jsx`** 及其 `index.css` 樣式（`.plan-comparison*`）。
- **`ScheduleNotice.jsx`** 還原為 PR #27 之前的版本。`DashboardPage` 只在 `level === 'error'` 時傳入，橘色資訊通知不再顯示，排課失敗的錯誤仍會顯示。儲存課表只顯示既有的 toast。
- **`RemoveReasonDialog.jsx`**：
  - 拿掉「不提供原因」，只列 7 個原因。
  - 開啟時不預設勾選。
  - 再點一次已選的原因可以取消。

未修改後端。
