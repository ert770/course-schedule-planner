# MyFCU 匯入的修課紀錄：讀取時補分類擴充為五步

日期：2026-11-24

## 背景

MyFCU 匯入的修課紀錄沒有修別與畢業分類。2026-11-23 的整合（ADR-034）只用資工科目表在讀取時補分類，體育、國防、通識領域課與外系課都會落到「未分類」。以隊友匯入的帳號（user 2）為例，39 筆可用紀錄中 12 筆未分類，畢業進度的通識少算約 10 學分、系外選修算成 0。使用者同意依專案既有規則擴充。

## 修改檔案

| 檔案 | 內容 |
| --- | --- |
| `server/src/db/database.js` | `fillMissingHistoryCategories(row, context)` 改為五步（課名不計畢業 → 科目表 → 課程表通識 → 非本系開課先算系外 → 未分類）；新增 `loadHistoryClassificationContext()`，只為分類空白的列查課程表與學生系所，失敗時退回前兩步 |
| `server/test/importedHistoryCategories.test.js` | 新增 IH5～IH9：不計畢業、通識、系外（含別系必修、進修部、非系所單位）、本系課號與課程表查不到維持未分類、查詢失敗時不丟錯誤 |
| `docs/DATA_SCHEMA.md`、`docs/API_SPEC.md`、`docs/DECISIONS.md`（ADR-034 補記） | 讀取規則 |

## 影響範圍

- 只影響修別或畢業分類為 NULL 的列（目前只有 MyFCU 匯入的帳號）。分類已存在的列一律不改；demo 與 Persona 帳號的結果不變。
- 讀取時多一次查詢（只在有分類空白的列時）。

## 測試與驗證

- `npm test`：1954 項，1940 通過、0 失敗、14 略過（13 個需要 Playwright、1 個既有略過）。
- 唯讀查證（共用 MySQL，只看前綴與學分）：
  - user 2 改前：必修 44、選修 10、通識 10、系外 0、未分類 23（另有體育、國防 3 學分落在未分類）。
  - 第一版（套用系外選修機械條件）：通識 20、系外 3、未分類 7（日文 2 筆為語言中心開課、企管 1 筆只有進修部班次）。
  - 使用者決定「都先算系外」後：必修 44、選修 10、通識 20、系外 10、未分類 0；體育、國防歸不計畢業。
  - 27 個帳號全部讀取成功；除 user 2 外沒有分類空白的列。
- 瀏覽器：D1249697 的畢業進度 API 回 200，未分類 0，與原本一致。匯入帳號是隊友的真實資料，未登入驗證畫面。
