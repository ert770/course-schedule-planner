# 手動加選跨方案、重排與重新整理保留

日期 2026-11-25

## 修改內容與影響範圍

- `client/src/contexts/ScheduleContext.jsx` 依登入帳號在瀏覽器保存手動加選。切換方案時合併並依班次去重，使用現有課表驗證檢查衝堂、重複班次與學分上限。移除課程成功後更新保存清單。載入舊快照時，若合併後無法通過驗證，先保留手動加選。
- `client/src/pages/DashboardPage.jsx` 重排時將手動加選送作指定課程，結果缺少手動加選時保留目前課表。切換方案驗證失敗時顯示原因並保留原方案。時間未定的已選課程在課表下方仍可查看及移除。
- `docs/SCHEDULING_LOGIC.md` 記錄手動加選的生效、驗證與移除規則。既有後端 API 與資料表沿用。

手動加選在同一瀏覽器、同一登入帳號內保存。既有快照未記錄哪些課是手動加入，因此不會將舊快照內的所有課標記為手動加選。

## 驗證

- Chrome 實際操作搜尋加選、切換方案、重排、重新整理、切換登入帳號及移除。以修改前的建置做對照，原版切換後會遺失加選，修改後可切換至相容方案並保留課程。另一方案的第二個時段衝堂時顯示課名並留在原方案。
- 確認重排請求帶入手動班次，結果漏掉手動班次時保留目前課表。無快照、快照可合併、快照衝堂與帳號切換情境均通過。手動移除後切換及重新整理均未出現該課，也不再隨重排送出。時間未定的手動加選切換及重新整理後仍可在課表下方查看。瀏覽器 console 未發現錯誤。
- 瀏覽器驗收使用隔離的測試帳號與方案回應，課表驗證使用現有後端驗證函式。
- 前端 lint、build、後端入口語法檢查與 `git diff --check` 通過。完整測試 1,989 筆通過、14 筆跳過、0 筆失敗。
