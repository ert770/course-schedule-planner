# 首頁排課不再用固定的 25 學分蓋掉個人學分上限

## 修改日期

2026-10-07

## 1. 問題

以測試 Persona D0009003（學分上限 18）在瀏覽器驗收時，首頁排出 **8 門課、21 學分**，超過這位學生自己的上限。

原因在前端。`DashboardPage.jsx` 每次排課都送出 `maxCredits: 25`，而後端的取值順序是
`input.maxCredits ?? prefs.targetCreditsMax`——請求裡有值，個人設定就不會被讀到。
同一個檔案在 2026-09-10 才修過一模一樣的問題（寫死 `minCredits` 讓四年級下限從未生效），
當時只拿掉了下限，上限留著。

之前沒被發現，是因為既有四個帳號的 `max_credits` 剛好都是 25。10 位 Persona 的上限是
10～25 不等，有 7 位不是 25，問題才浮現。

## 2. 修改檔案

| 檔案 | 內容 |
| --- | --- |
| `client/src/pages/DashboardPage.jsx` | 排課請求不再送 `maxCredits`；方案比較（反事實）也不再送 |

後端沒有修改。沒有設定個人上限的使用者，後端原本就會退回校規上限 25（申請超修為 30）。

## 3. 影響範圍

- 個人學分上限低於 25 的使用者：首頁排課與方案比較會遵守自己的上限。
- 上限為 25 或未設定的使用者：結果不變。
- AI 對話排課與「排課」頁原本就沒有送固定上限，不受影響。
- Persona 模擬腳本（`personaChoiceSimulation.js`）本來就讀個人上限，修正後才與首頁看到的方案一致。

## 4. 測試與驗證

- `npm run lint`、`npm run build`（client）：通過。
- 瀏覽器（本機，以 D0009003 登入，個人上限 18）：

  | | 修正前 | 修正後 |
  | --- | --- | --- |
  | 首頁排課結果 | 8 門課、21 學分 | 6 門課、17 學分 |
  | 方案數 | 2 | 2 |

  - 修正後兩個方案都是 17 學分；偏好面板勾選的四項（集中排課、不排早八、星期一排空、午休留空）
    與資料庫一致；課表星期一與第一節皆無課。
  - 切換方案正常：綜合方案有「安全程式設計、嵌入式系統」，輕鬆導向方案換成
    「資訊安全管理、電腦視覺與擴增實境」，切回後還原。
  - 沒有按「符合」，所以沒有寫入任何方案選擇事件。
  - console 沒有新增錯誤（既有的 401 與連線失敗訊息是登入前與先前後端停止時留下的）。
- 未修改後端與排課邏輯，未執行後端測試與 S1–S10。
