# 協同過濾與 User Embedding：階段 1 標籤空間課程向量

- 日期：2026-10-14
- 對應構想：[協同過濾與 User Embedding 的搭建方式](./2026-10-14-cf-user-embedding-design.md) 3.2.1、第 7 節階段 1
- 前一步：[階段 0 現況量測](./2026-10-14-cf-embedding-stage0-baseline.md)
- 決定（使用者，2026-10-14）：**常見主題（`too_common`）以低權重納入向量**
- 性質：新增純函式模組與唯讀檢查腳本；**未接進排課、探索或任何 API**，使用者看不到變化

---

## 1. 結論

1. 標籤空間向量建好了：當學期 2,004 門課、2,171 個向量標籤，只有 4 門課沒有向量。
2. **人工抽查 20 門課、99 個最近鄰居，我判斷約 86 個合理（約 87%）。** 同主題的課
   （資料庫、半導體、會計、法律、通訊、微處理機、物聯網）幾乎都找得很準。
3. 常見主題納入後確實派上用場：「機器學習」「人工智慧」「Python」現在能把 AI 相關課程連起來
   （例如「人工智慧與大數據分析」的前 5 名全是資料科學與 AI 課）。它們的 idf 為 2.25～3.84，
   約是最稀有標籤（6.91）的三分之一到一半，不會主導相似度。
4. **不合理的鄰居集中在一個原因：描述上課形式而非主題的標籤**（互動教學、學術討論、研究生、
   人文社會科學）。它們只出現在少數課程，idf 反而很高。試過依分類排除，沒有改善（見 4.2），
   這次不處理，列為待決定。

這是我一個人的判斷，建議你看一下 `stage1.md` 的 20 組結果（第 6 節有路徑）。

## 2. 做了什麼

### 2.1 `server/src/skills/tagVectorSpace.js`（新增）

| 函式 | 作用 |
| --- | --- |
| `isVectorEligibleTag(tag)` | 向量用的標籤資格：可跨課比對的標籤，加上 `too_common`。`single_course`（只在一門課出現，不可能讓兩門課相近）與 `explicit_generic`（團隊合作、實習等）排除 |
| `vectorTagsOf(rawTags)` | 課程原始 `rag_tag` → 向量可用的標準標籤 |
| `buildCourseTagVectors(courses)` | 以課號為單位（同課號多班次取聯集），`idf = ln(課程數 / 有該標籤的課程數)`，值為 idf 的稀疏向量 |
| `cosineWithContributions(a, b)` | 餘弦相似度，並列出每個共用標籤的貢獻（加總等於相似度），推薦理由可以直接引用；任一方為零向量時回傳 `null`（無法比較，不是不相似） |
| `nearestCourses(index, code, { k, filter })` | 最相近的 k 門課 |

**與現有標籤興趣檔案分開**：這是另一套資格規則，`rag-tag-interest-v1` 的 `s_tag` 計算完全沒改。

### 4.2 不合理的原因與試過的修正

不合理的鄰居幾乎都只靠一個標籤連起來，而那個標籤描述的是**上課形式或身分**，不是主題：
互動教學（7 門課）、學術討論（6）、研究生（3）、人文社會科學（6）。它們出現的課少，idf 高，
一個就能撐起 0.28～0.46 的相似度。

**試過**：把只屬於「課程活動與評量」「學習階段與課程情境」「通用能力與職涯」三個主分類的
92 個標籤排除。**結果沒有改善**：上面四個標籤其實被分在「教育、學習與研究」或「自然科學」底下，
沒被排除；反而「批判性思維」被排除後，先秦諸子的鄰居變差。所以這版不採用類別排除。

**可行的方向（待決定）**：

1. 人工列一份「形式標籤」清單（互動教學、學術討論、研究生、專題報告……）只在向量中排除。
   簡單直接，但要維護清單。
2. 要求兩門課至少共用 2 個標籤才算相近。會減少單一標籤造成的誤判，但也會讓標籤少的課找不到鄰居。
3. 等階段 2 的標籤相近表（文字 embedding）完成後再看。主題相近的標籤會互相加分，
   單一形式標籤的影響相對變小。

我傾向 3 先做、再看是否還需要 1，因為階段 2 本來就要做。

### 4.3 其他觀察

- **講課與實習課成對出現**：「成本與管理會計(二)」與「成本與管理會計(二)實習」（課號多一個 `P`）
  相似度 0.95。推薦時應視為同一門課，到階段 4（探索清單）時處理。
- **不同系同名的課**（三門「機器學習」）會互相是最近鄰居。這對「推薦相近的課」是對的，
  但呈現時要標出開課系所。

## 5. 對老師提供的 112～114 學年度課程大綱

尚未匯入資料庫。它對構想的影響：

| 用在哪裡 | 影響 |
| --- | --- |
| 歷史修課的向量 | **直接受益。** 資料庫目前只有當學期課程，歷史課本學期沒開就查不到標籤（階段 0：D1249697 的 25 門非必修已修課只有 18 門查得到）。有了歷屆大綱，大多數歷史課都能有向量 |
| 階段 2 的課程文字向量 | 受益，可以算到更多課 |
| idf | 要決定 idf 用「當學期」還是「三年合併」計算；合併後同一門課會出現多次，要以課號去重 |
| 協同過濾 | **間接受益，不會直接補足。** 協同過濾需要的是「哪些學生修了哪些課」的互動資料；課程大綱是課程內容，不是學生行為。它讓歷史修課能對到課程、讓冷啟動的內容式推薦更準，但跨使用者的樣本數仍然取決於真實使用者人數 |

要用這批大綱，還需要：

1. 大綱檔案的位置與格式。
2. 這批課程的 `rag_tag`：目前的標籤是由課程資料另外產生的，新課程要用同一套流程產生標籤，
   並對到現有的標準標籤目錄（`rag-tag-catalog-2026-10-09-v2`）。
3. 匯入方式：寫入共用 MySQL 前要另外確認，因為 `Courses` 表目前只有當學期，
   多學期資料可能影響排課與搜尋的篩選邏輯，必須先確認這些地方都有依學期篩選。
