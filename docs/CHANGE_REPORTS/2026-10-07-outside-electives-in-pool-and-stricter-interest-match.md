# 排課候選池納入系外選修；興趣比對改嚴；保留一個名額給系外

## 修改日期

2026-10-07

## 1. 起因

Persona 模擬試跑的檢視中（見
[任務 3B 報告第 12 節](./2026-10-07-roadmap-10-3b-persona-simulation.md)），一位設定「最近對管理、金融
有興趣」的學生拿到的三個方案裡沒有任何一門管理或金融的課。查下去是排課引擎的兩個問題：

1. **興趣比對是把所有欄位接起來做包含比對。**「管理」命中「系統管理」「健康管理」「水資源管理」
   與課程說明裡任何一句「專案管理」，UNIX、養生文化與水資源通識因此拿到最高的興趣分數。
2. **候選池沒有系外選修。** 規格把「任何系所的選修」列為一般候選，畢業配額也有系外這一格，
   但候選池查詢從未放進來（2026-10-03 任務 4 已記錄為待辦）。

## 3. 主要改動

### 3.1 候選池

`filterCategorizedCourses()` 在 `schedulingPool` 模式多放一類：**其他系所班級、與學生同學制的選修**。
範圍與課程搜尋的「系外選修」分類共用同一個判定（`isSameDegreeOutsideElective()`），年級規則照舊
（開課年級為 0 或與學生同年級）。外系必修、其他學制、外系他年級的課不納入。一般搜尋與 Agent 查課不變。

能不能認列不在這裡判定——`scheduler.js` 的 `prepareCandidates()` 本來就會對每門候選呼叫
`evaluateOutsideElective()`，不能認列的剔除並把原因記進 `excludedCourses`。這段邏輯一直都在，
只是先前沒有系外選修會走到。

### 3.2 系外選修的提醒

原本「須向系辦確認」「大一層級課程難度需自行確認」「已排除 N 門不符合認列條件」三則是對**候選**
統計的。候選池納入系外選修後每位學生有一兩百門，照舊會讓每次排課都出現
「候選課程中有 190 門系外選修須向系辦確認」。

現在前兩則改由 `outsideElectiveWarnings(plan)` 產生，只列**排進該方案的**系外選修，greedy／repair
與 MILP 方案共用。第三則統計警告拿掉，原因仍逐門留在 `excludedCourses`。

### 3.3 興趣比對

| 位置 | 命中條件 |
| --- | --- |
| 課名 | 包含關鍵字 |
| 修課路徑、主題標籤 | 與關鍵字相同，或以關鍵字開頭 |

英文不分大小寫。不再比對課號、教師、系所、分類與課程說明。

實測（9002 的候選池加上系外選修，以課名去重）：

| 關鍵字 | 舊規則 | 新規則 | 新規則留下的例子 |
| --- | ---: | ---: | --- |
| 管理 | 101 | 17 | 資訊安全管理、目標管理與行銷組織、敏捷專案管理、組織行為 |
| 金融 | 18 | 12 | 投資學、經濟與日常生活、世界經濟論壇 |
| 網路 | 26 | 10 | 互連網路、系統安全、資訊與網路安全 |
| 人工智慧 | 24 | 18 | 人工智慧導論、人工智慧倫理與治理 |
| 語言 | 70 | 48 | 程式語言、印尼語(一) |
| 資訊安全 | 8 | 8 | — |
| 硬體 | 5 | 0 | （舊規則命中的是 JAVA、倉儲物流等，全是雜訊） |
| 遊戲 | 6 | 0 | （同上） |

這是字面啟發式，不是語意判斷。已知限制寫在 `SCHEDULING_LOGIC.md`：關鍵字只在標籤後半時
（「離散數學」之於「數學」）要靠課名命中；課名包含仍會放進「資訊安全管理」；同義詞比不到。

## 5. 系外名額幾乎分不到 → 保留一個名額給系外

只做前兩項時，候選池有系外選修，但 21 組結果裡**沒有任何一個方案排入系外選修**。原因是畢業配額的規則
（`buildBreadthSequence()`）：通識與系外合計最多兩門，每個名額給「本學期目標較大者」。
通識的本學期目標通常大於系外（例如 9003 是 7.33 對 3、9008 是 4.8 對 1.2），所以兩個名額都給通識。
系外缺口為 0 的學生（user 1、2、4）本來就不該排。

這表示 9008 這種「修金融科技微學程、想排商學院選修」的學生仍排不到任何商管選修。

**專案負責人於 2026-10-07 決定改配額規則：保留一個名額給系外。** 實作為：系外學分仍有缺口，
且這次的興趣關鍵字命中至少一門可認列的系外選修候選時，兩個名額保證其中一個是系外；這個名額
先用命中興趣的系外選修填，都排不進去才退回其他系外選修。其餘情況與原規則相同。

改完後同一組 21 個輸入：

| 項目 | 結果 |
| --- | --- |
| 排入系外選修的方案 | 13 個（全部出現在有設興趣、且系外有缺口的 9002、9003、9008） |
| 沒有設興趣的輸入 | 與改規則前相同，系外 0 門 |
| 系外缺口為 0 的 user 1、2、4 | 不受影響 |
| 安全檢查 | 全數通過 |
| 9008「管理、金融」 | 排入「組織行為」 |

要如實說明的兩點：

- **排進去的系外選修不一定與興趣有關。** 命中興趣的系外課排不進去時會退回其他系外選修：
  9003「管理、金融」排到的是「專業實習導論」，9008「人工智慧」排到的是「組織行為」。
  名額是因為興趣才保留的，但填進去的課可能只是補系外學分。
- **9001（大一）仍是 0 門**：必修已佔 24 學分，沒有空間。

多方案基準在這一步由 5 個通過 2 個變成通過 3 個（`fixed-courses-control` 產出 4 個方案）。

## 6. 影響範圍

- 所有設定了興趣關鍵字或修課路徑的使用者：興趣命中變少、變準，排入的選修與通識可能不同。
- 所有使用者：候選池變大；`excludedCourses` 多出不能認列的系外選修（實測 6～13 門）。
- 排課警告少了三則對候選的統計，多了兩則只在排入系外選修時才出現的提醒。
- Choice Perceptron 的興趣軸特徵定義跟著改變。目前真實 `plan_chosen` 只有 4 筆，影響有限，
  但修改前後的興趣分數不可直接比較。
