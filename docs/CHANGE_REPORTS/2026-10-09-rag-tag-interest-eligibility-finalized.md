## 主要改動與確認來源

原沙盒執行 MySQL 報表回 `ENOTFOUND`；改用本機權限環境後成功。使用者看到摘要並確認維持 `>2%` 高頻排除，再明確核准資格寫入與 commit／push。寫入前重新執行既有唯讀報表，核對全部統計仍一致，才按 canonical tag ID 更新目錄。資料庫僅讀取，未修改表結構或資料。

課程數是穩定課號聯集的數量，不等於 MySQL `Courses` 表的原始列數。班次先合併，同一課的別名與多條分類路徑不重複計數。

- 分類版本維持 `rag-tag-catalog-2026-10-08-v1`；資格版本為 `rag-tag-eligibility-2026-10-09-v1`。分類 ID、別名來源、原始寫法、分類路徑與來源列均保留，寫入前做完整結構比較。
- 目錄資格狀態改為 `reviewed_post_alias_course_recount`，每個標籤保存學習／配對資格、出現課數、比例、原因與資格版本。
- 新增頂層 `eligibilityRecount`：資料來源、計算時間、核對日期、課號／canonical 集合摘要 SHA-256 與統計。快照沒有 DB 連線憑證或使用者資料。
- 通用與高頻標籤的兩種資格皆為 false；單課標籤可學習但不可跨課匹配；其餘為兩種資格皆 true。
- 「人工智慧」（97／2,004）、「機器學習」（62／2,004）及 Python（80／2,004）均因超過 2% 被排除，此規則已經使用者確認。廣泛主題仍可保存在分類層供探索，不自動把分類下所有細標籤設為正向。
- `interestTagEligibilityReport.js` 仍是唯讀工具，沒有新增自動寫回選項。重新匯入 Excel 會重建 pending 目錄，需要重新執行 DB 報表及核對才能寫回新資格。
- 必修課排除須依使用者 scope 在事件層執行，留給階段 3；本次全域頻率不任意剔除必修。
