## 主要改動

### #18 authenticated identity 與 Profile schema

- 登入後建立簽名、HttpOnly、SameSite=Lax session cookie，canonical identity 固定為學號。
- Profile、Schedule、Chat、Graduation、watchlist 與 saved schedules 全部從 session 取得身分；未登入回 401，request 冒用另一個 ID 回 403。
- 前端 API 全部開啟 credentials 並停止傳 user ID；`/auth/me` 與 `/graduation/me` 改為 session 契約。
- 前端 onboarding／setup localStorage key 改為 per-user 命名，登出不再呼叫 `localStorage.clear()`；移除畢業頁硬編碼學號 fallback。
- 新增 Profile schema v1 normalizer／validator；GET 與更新後的 Profile response 均回傳 `schemaVersion: 1`。
- 建立 `student_id UNIQUE`、`class_name`、`profile_schema_version` migration，支援 dry-run、執行前備份、重複執行檢查及 rollback。shared MySQL 未經協調不執行 DDL。

### #19 自動重補修與 latest-attempt

- `courseHistory` 契約固定為 11 個必要欄位；demo 53 筆資料皆通過契約測試。
- 同一課號依 `academicYear + semester` 取最新紀錄；先失敗後通過視為完成，最新仍失敗且為必修才成為重補修來源。
- 移除公開的 `retakeCourseIds`／`failedRequiredCourseIds`。重補修只由 Profile `courseHistory` 自動推導，舊 client 傳入不生效。
- 自動將失敗必修映射到本學期相同 `catalogCourseCode` 的所有 sections，固定排在本學期必修之後、其他課程之前；多班次最多排一班。
- 本學期無開課時回傳下學期重修 warning；有開課但受衝堂／硬限制無法排入時回傳調整課表 warning。
- `withdrawn`、`transferred`、`exempted` 未在 #19 實作，已移入 roadmap #23 的畢業認列狀態模型。

## 影響範圍

- 所有 user-scoped API 現在必須先登入；舊 client 若只送 `userId` 而沒有 session 會收到 401。
- 排課結果會因歷史不及格必修自動增加重補修課程或 warning。
- 前端開發環境支援 `VITE_API_BASE` 與隔離測試代理；`VITE_E2E_BYPASS_SETUP` 只在 DEV 且 `BROWSER*` fixture 帳號生效，避免瀏覽器驗收寫入 shared Profile。
- `DATA_DIR` 可在隔離驗收時指向 fixture；預設仍為正式 `server/data`。
