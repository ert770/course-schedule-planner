# AI 對話推薦品質修正

- 日期：2026-10-15
- 來源：[s_vec／s_cf 切 active 與 10 位 Persona 實測](./2026-10-15-active-switch-and-persona-ux-test.md) 第 5 節第 1～3 項
- 性質：**使用者看得到的變更**（AI 對話的回答內容與回應時間）；另修正一個前端 React 重複 key 錯誤。

> 以下 A/B 用的是測試 Persona（9001～9010，模擬帳號）的真實資料與真實 OpenAI 呼叫；只驗證功能，不代表真實使用者的推薦效果。

---

## 1. 結論

1. **根本原因不是模型捏造，是忠實度檢查誤判**。伺服器只記錄違規數量，所以先前看不出來；這次把違規代號寫進日誌、
   並加診斷用的回呼取得原回答後，發現被判違規的幾乎都是正常句子：轉述使用者條件的引號（「英文授課＋資安或演算法」）、
   Markdown 粗體黏著課名（「**社會企業實作專題」）、說明「資格不符所以不推薦」、表格沒有教師欄等。
   一判違規、修正又失敗，就整則換成備援回答「目前可確認的課程資料如下…」並列出證據帳本前 8 門課，看起來就像答非所問。
2. **A/B（10 位 Persona 的原始問題，真實 AI）**：

   | | 修正前（10-14 瀏覽器實測） | 修正後 |
   | --- | --- | --- |
   | 給出針對問題的回答 | 1／10（其餘 9 題退回課表清單） | **10／10**（0 題落入備援；部分由修正器修好） |
   | 每題時間 | 約 57～95 秒 | 13～42 秒 |
   | 單題課程查詢次數 | 最多 20 次 | 上限 4 次 |
   | 查不到時 | 列出無關的課 | 明說查不到，並建議放寬哪個條件 |

3. **仍然擋得住捏造**：引號或散文中的捏造課名（「量子魔法課程」）、資格與畢業誇大、教師或學分不符、把被排除的課說成推薦，
   原有測試與新增測試都仍會攔下。

## 2. 修正內容

### 2.1 忠實度檢查（`server/src/services/explanationFaithfulness.js`、`sentenceFacts.js`）

| 誤判 | 修正 |
| --- | --- |
| 轉述條件的引號被當成課名（「英文授課＋資安或演算法」「課堂討論多」「社會議題、哲學」「午休不排課」） | 引號內容出現在使用者訊息裡、含條件分隔符、含條件用詞（不排、避開、優先、重視、為主…）、是偏好標籤或課程類別名稱、或同一子句前面有「符合／依／例如／改為／擴大到／關鍵字…」時，不視為課名 |
| Markdown 粗體黏著課名 | 比對前去掉 `**`、`__`、反引號 |
| 「人生哲學等課程」「校外專業實習」（被切在「實習」，實際課名有「(三)」） | 以「等課程」前的課名、或「片段＋括號序號」比對已知課名 |
| 一般敘述被切成課名（「以上課程」「不限課程」「的選項」「仍需以課程描述」「概論性課程」「替你保證課程」「方向」「規則」） | 指示詞或範圍詞開頭、以「的」開頭、夾帶人稱或動詞、複合名詞（課程描述／地圖…）、形容詞性（概論性）都不算課名 |
| 「一般選修避開」切出「避開」 | 動賓片語只看「推薦／加選」，不看類別名稱裡的「選修」 |
| 「資格不符，所以不推薦」判成誇大資格 | 句子含「資格不符／不能修…」時不算資格宣稱 |
| 「…未列入，因不認列為系外選修」判成推薦被排除的課 | 句子是在說明未排入／不認列時不算推薦；推薦動作只認「推薦／加選／建議修」 |
| 「其中體育 1 學分不計入畢業學分」判成提出畢業門檻 | 只有「才能／即可／就能畢業」或「畢業門檻／要求…學分」才算畢業規則 |
| 表格沒有教師欄時把學分當成教師 | 依儲存格內容判斷教師（2～5 個中文字的人名）與學分（純數字），不假設固定欄位順序 |
| 「目前還不能產生課表，需要確認…」判成未揭露未完成 | 揭露用語加上「還不能、還沒、需要確認、等你確認…」 |

### 2.2 備援回答

- 只列**原回答提到、且資料確認過**的課，並說明「原本的回答有部分內容無法和課程資料對上」；不再端上證據帳本前 8 門
  （先前會把使用者剛移除或無關的課列出來，也是「對話把剛移除的課加回來」這個現象的來源）。
- 使用者沒問評價時，不再附上「無法判斷是否涼或好拿分」。

### 2.3 查詢工具與提示詞（`agentService.js`、`promptService.js`、`docs/PROMPT_DESIGN.md`）

- `query_course_db` 新增選填 `language`（`English`／`中文 (Chinese)`），全英授課用參數篩選。
- 一回合最多查 4 次課程；超過時不執行，回給模型「依已查到的結果回答」，不記成失敗的操作。
- 提示詞：條件放進同一次查詢；查不到就直說並建議放寬；描述使用者條件用一般文字；
  使用者提到的系所年級和資料相同時不要提議更新。
- `update_student_profile`：與目前 Profile 相同的欄位先拿掉，全部相同就回「不需要更新」
  （A/B 中 9001、9004 原本都被「要不要把年級更新成大一／大四」打斷，沒有回答選課問題）。
- 日誌記錄違規代號（不記內容）；`handleChat(..., { onFaithfulness })` 供診斷與測試。

### 2.4 前端

- `CourseDetailModal.jsx`「它勝過」清單改用班次 id 當 key：同一門課的兩個班次同名，React 報重複 key。
