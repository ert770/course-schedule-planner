- 日期：2026-10-15
- 對應：[協同過濾與 User Embedding 構想](./2026-10-14-cf-user-embedding-design.md) 5.1、階段 8；
  前一階段見[階段 7 報告](./2026-10-14-collaborative-filtering-stage7.md)
- 性質：**使用者看得到的變更**（排課結果改變），另修正 Persona 實測中發現的 4 個問題。

> **Persona 資料是模擬的**：9001～9010 是組員建立的測試人物，以下的興趣推論與操作都是我扮演他們做的。

## 1. 結論

1. **`s_vec`、`s_cf` 預設 active**（使用者決定）。依構想 5.1 各自加分、分數明細分開列：
   單課 `+ α × 基礎分 × s`，方案 `方案偏好分 × α × 平均 s`。必修、指定、實習課不加分。
   - 構想原訂 `s_vec` 先 shadow 觀察、`s_cf` 等真人 ≥ 15 才 active；這次依使用者決定提前。
     `s_cf` 在共現表為空時是 null、等於不加分；目前正式表只有 1 位真人、0 組配對，所以實際上還沒有作用。
2. **四類測試都跑過**：單元（`npm test` 1,581 項、前端 9 項）、整合／黑箱（對執行中的伺服器呼叫全部 41 個 API 端點、54 個案例）、
   系統（10 位 Persona 的 active／off A/B）、瀏覽器 UX（10 位 Persona 依各自興趣操作，寫入 259 筆互動事件）。
3. **實測中發現並修正 4 個問題**（第 4 節）：新手引導頁會悄悄撤回協同過濾同意、歷史回饋編輯模式漏記「普通」、
   全校查詢的授課語言篩選永遠 0 筆、手動加入的課在「套用偏好排課」後消失。
4. **另有 9 項發現未修正**（第 5 節），其中最明顯的是 AI 對話：回答忠實度檢查常判定違規，改用備援回覆
   「目前可確認的課程資料如下…」，推薦類問題幾乎都變成列出課表。

## 3. 測試

### 3.1 單元測試

- `server/src` 與 `server/scripts` 全部 `node --check` 通過。
- `npm test`：1,581 項，1,580 通過、1 略過、0 失敗（含 S1～S10）。覆蓋率（`--experimental-test-coverage`）：
  行 90.8%、分支 83.3%、函式 91.0%；覆蓋率低的主要是 API 路由與 `memoryService.js`，由 3.2 的黑箱測試補上。
- 前端 `src/services/*.test.js` 9 項通過（這些測試沒有掛在任何 npm script，需手動 `node --test`）；`npm run lint`、`npm run build` 通過。
- 新增：VI-6、VI-7、CS-4（active 改變選課、必修不加分、s_vec 與 s_cf 分開列）、CN-3（Persona 一律模擬）、
  LANG-1（授課語言篩選）、前端 consent adapter 3 項。

### 3.2 整合／黑箱測試（對執行中的伺服器）

以 Persona 9010 登入，逐一呼叫全部 API（41 個路由定義），54 個案例全部符合預期：

- 權限：未登入 401、密碼錯 401、缺欄位 400、讀他人畢業檢核 403。
- 隱私：未同意必要用途 400；**只勾協同過濾不勾個人化 → 伺服器記為不同意**；匯出不含 subject ID；刪除帳號只測錯誤確認詞 400（未真的刪除）；重設個人化。
- 課程、評價、探索（兩種模式）、興趣探索卡、歷史回饋、畢業檢核、排課、反事實、驗證、儲存、已存課表、互動事件（含超過 50 筆 400）、關注清單、AI 對話（含空訊息 400）、登出。
- **黑箱發現（未修）**：登出只清掉瀏覽器 cookie，舊 token 7 天內重送仍有效（無狀態簽章 session）。已另開任務。

### 3.4 瀏覽器：10 位 Persona UX

全部伺服器先關閉再以 `preview_start` 重開（同時修正 `.claude/launch.json` 前端代理埠號，先前 502 的原因）。

## 5. 發現但未修正

> 第 1～3 項已於同日修正，見 [AI 對話推薦品質修正](./2026-10-15-ai-chat-recommendation-quality.md)。

1. **AI 對話的推薦品質**（已修正）：伺服器日誌顯示回答忠實度檢查判定違規（`fallback=true`）後，改用備援回覆
   「目前可確認的課程資料如下…」並列出課表，推薦類問題（「有英文授課的資安課嗎」）幾乎都變成這樣，還常提到「涼」。
2. **AI 對話會加回剛移除的課**（已修正，來源是備援回答列出整份證據帳本）：對話排課沒有沿用主頁的「本次迴避」（9004、9005、9006、9008 都出現）。
3. **AI 對話偶爾很慢**（已修正，查詢上限 4 次）：一次請求連續呼叫 `query_course_db` 8 次以上，約 60～90 秒。
4. **探索頁推薦剛按「沒興趣」的課**：9005 對「家計經濟學」按沒興趣（並選了標籤），「依修課與興趣」仍排在第一。
5. **全校查詢「科目名稱」也搜尋課程描述**：`SearchPage.jsx` 把課名與描述都送成同一個 `keyword`，標籤與行為不一致。
6. **推薦理由文字矛盾**：「它符合你的偏好」下面接著「它沒有命中你設定的任何偏好」。
7. **儲存課表沒有任何成功提示**（`ScheduleNotice` 不顯示）。
8. **「個人化來源」多數 Persona 顯示「尚未表達偏好」**，即使已有偏好標籤與數十筆互動。
9. **語意相似（課程文字向量本機原型）品質不穩**：從「Web程式設計」出發得到「水處理工程與設計」「鋼筋混凝土房屋設計」；
   沒有課程說明的課沒有結果。另外系列課缺先修資料，會推薦「西班牙文(四)」給只修過(一)(二)的人。

### 測試工具本身的限制

- 前幾位 Persona 的「重新排課」數字有部分是在排課完成前讀取（例如 9002 的 6 門／17 學分、9004 的 4 門／10 學分），
  9007 起改為等排課完成才讀；修正後重讀 9007 為 5 門／11 學分，沒有低於學分下限。
- 興趣探索卡的關鍵字規則太寬，部分 Persona 8 張都是「有興趣」（探索卡本來就依修課路徑挑選）。
- 全程 Flaky 測試未再出現（全套連跑皆 0 失敗）；先前的 2 項不穩定與登出 token 問題已另開任務。
