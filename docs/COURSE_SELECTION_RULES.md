# 逢甲大學選課規則

## 這份文件的性質

本文件記錄**學校官方公告的選課與畢業規則**，是排課邏輯與畢業學分判定的依據來源。每一項都附出處，未經查證者明確標示為「未確認」。

程式端對應檔案：

| 資料 | 檔案 |
| --- | --- |
| 各系畢業學分 | `server/src/data/graduationRequirements.js` |
| 系所與班級簡稱對照 | `server/src/data/departmentMapping.js`（來源為 `docs/DEPARTMENT_MAPPING.md`） |
| 節次與時間對照 | `server/src/utils/periods.js` |
| 資工系核心選修／選修／修課路徑 | `server/src/data/csCurriculum.js` |
| 通識共同必修（不計畢業學分） | `server/src/data/generalEducation.js` |
| 系外選修認列條件 | `server/src/skills/outsideElective.js` |
| 課程類別解析（必修／核心選修／系外選修） | `server/src/skills/courseCategory.js` |

修改任一程式檔前必須先更新本文件，兩者不得各自漂移。

### 通識共同必修 3 學分（**不計入畢業學分**）

| 項目 | 學分 | 說明 |
| --- | ---: | --- |
| 全民國防教育軍事訓練（國防科技） | 1 | 一年級必修，以學院別劃分，上下學期均開課 |
| 體育 | 2 | 一年級必修 |
| 班級活動 | — | 必修 |

排課時這三類要排進課表，但**不得計入畢業學分**。外籍生經國際處審核後可免修全部軍訓課程。

軍訓與體育的**選修**課程是否計入畢業學分，由各系修業須知自行訂定（例如運輸與物流學系規定體育選修至多 1 學分計入）。

#### 已實作

判定於 `server/src/data/generalEducation.js`，一律以**課名**為準——資料庫的 `Courses.type`
只有 `必修`／`選修` 兩種值，沒有「通識」類別可用，班級名稱也不可靠（`班級活動` 掛在
168 個不同的系所班級底下）。

| 判定 | 資料庫實際課名 |
| --- | --- |
| `name === '班級活動'` | 班級活動（0 學分必修，168 筆） |
| `name` 以 `體育` 開頭 | 體育(二)（1 學分必修，74 筆）、體育－羽球等體育選修 |
| `name === '國防科技'` 或以 `軍訓` 開頭 | 國防科技（1 學分必修，1 筆） |

排課結果因此回報**兩個學分數**：

| 欄位 | 意義 |
| --- | --- |
| `totalCredits` | 學期修習學分，用於 12～25 學分的上下限檢查。**含**這三類 |
| `graduationCredits` | 計入畢業的學分。**不含**這三類 |
| `nonGraduationCredits` | 兩者差額 |

每門排入的課另帶 `countsTowardGraduation` 與 `nonGraduationCategory`，前端據此顯示
「🎓 N 學分」與「🧮 計入畢業 M 學分」兩個標籤。

**未涵蓋**：軍訓選修（資料庫中的 `全民國防` 2 學分、`國防政策` 2 學分）採計方式由各系
修業須知自訂，資工系科目表未提及，因此**維持計入**。各系自訂規則（例如運輸與物流的
體育選修 1 學分）目前沒有資料，所有系所套用同一組判定。

## 六、資工系選修分類（已確認）

資工系必選修科目表的選修科目有 `c.` 與 `d.` 兩種前綴。逐門比對科目表本身的區塊後確認：

| 前綴 | 對應區塊 | 門數 |
| --- | --- | ---: |
| `c.` | **核心選修（12 學分）** | 15 |
| `d.` | **選修（16 學分）** | 53 |

`c.` 清單：物件導向設計(+實習)、密碼學、資訊與網路安全、網路程式設計(+實習)、電子學(+實驗)、數位系統設計(+實驗)、編譯器、程式語言、系統分析與設計、軟體工程開發實務、人工智慧導論。

**確認依據**：科目表「核心選修 (12學分)」區塊逐門列出的 15 門科目，與上方 `c.` 清單**逐門完全一致**，因此對應關係確定。`c.` 既然是核心選修，`d.` 即為選修。

**1 門的差距**：本節先前記為 `d.` 54 門。依科目表逐列可驗證的內容建表為 53 門，
`server/src/data/csCurriculum.js` 採用 53 門。差 1 門可能是先前計數或本次來源轉換有誤，
與 PDF 原件核對後再補。這不影響分類正確性——分類是逐門比對，不是靠總數。

### 已實作

資料在 `server/src/data/csCurriculum.js`，分類函式為 `classifyCsCourse()`。

**比對必須同時要求課程物件的 `catalogCourseCode`（由 MySQL `Courses.subid3` 映射）
以 `IECS` 開頭**，不能只比對課名：

| 課名 | 資料庫中實際存在的 | 只比課名的後果 |
| --- | --- | --- |
| 網路程式設計 | 通訊工程學系 `COME3016` | 通訊系的課被當成資工系核心選修 |
| 電子學 | 機電系 `MCAE3103` | 機電系的必修被當成資工系核心選修 |
| 系統分析與設計 | 都資系 `UPSI2008` | 同上 |

反過來，本系的課也可能掛在非系所班級底下（密碼學 `IECS3052` 開在 `資通安全學程`），
因此判定依課號而不是班級名稱。

分類結果會覆寫排課引擎的 `course.category`（原值保留在 `sourceCategory`）。這一步是必要的：
**資料庫的 `type` 只有 `必修` 與 `選修` 兩種值**，排課引擎類別優先度表裡的
`核心選修`、`通識`、`系外選修` 從來不會出現在資料中，那三條優先度規則在此之前從未生效過。

## 八、必修不得換班（僅確認資工系，已實作）

資訊工程學系選課公告明確寫**不接受必修課程換班級的要求**。轉學或轉系學生需自行預選其他班級必修課程，但不保證選得上。

因此必修範圍收斂到**班別**（資訊三甲／三乙／三丙／三丁），而不只是系所與年級。

### 已實作

`server/src/skills/courseScope.js` 的 `parseClassName()` 會解析出 `classSuffix`
（`資訊三甲` → `甲`），`isRequiredForStudent()` 再比對學生的班別。

| 情況 | 處理 |
| --- | --- |
| 課程班別 = 學生班別 | 這位學生的必修 |
| 課程班別為**合班**（`資訊二合`） | 全年級共同修習，仍算這位學生的必修 |
| 課程班別為同年級其他班（`資訊三乙`） | 別人的必修，整批排除 |
| 學生未設定班別 | 維持系所 + 年級判定，並警告「未設定班別」 |
| 班別與系所或年級不一致 | 忽略班別設定並警告，不得靜默排除全部必修 |

**合班必須視為本班**：資料結構與資料結構實習開在 `資訊二合`，是資訊二甲～二丁全體的必修。
只做嚴格字串比對會讓資訊二甲的學生漏掉這兩門必修。

### 班別的儲存位置

**目標狀態是 `User_Profiles.class_name` 欄位。** 該表與組員共用，本專案不自行
`ALTER TABLE`；程式已具備該欄位的讀寫，`server/src/db/database.js` 的
`hasUserProfileClassNameColumn()` 會偵測欄位是否存在，**欄位一新增就自動改走 SQL，
不需要再改任何程式**（偵測結果快取，需重啟後端生效）。

欄位還沒出現前的後備順序（讀取優先度亦同）：

| 順位 | 位置 | 適用 |
| ---: | --- | --- |
| 1 | `User_Profiles.class_name` | 欄位存在時的唯一真相來源 |
| 2 | `users.json` 的 `className` | demo 登入使用者（`studentId` 或 `id` 對得到） |

**兩者都沒有時班別無處可存，寫入會拋錯。** 這種使用者在 `User_Profiles` 裡、
但該表沒有 `class_name` 欄位，`users.json` 也沒有他的列。原本的第 3 順位
`user_preferences.json` 已於 2026-08-11 刪除（同一份 profile 存兩處必然漂移）。
明確失敗優於「儲存成功」地丟掉——後者會讓下一次排課無聲地退回系所 + 年級。

優先順序的決策邏輯抽成純函式 `pickClassNameTarget()` 並有測試涵蓋。

前端在 `SetupPage` 的「基本資料」提供班別下拉選單，選項由 `GET /api/courses/classes`
依系所與年級從課程資料現場推導，不在前端複製系所簡稱對照表。

**其他系所是否有相同規定尚未查證。**

## 九、系外選修條件（僅確認資工系，已實作）

資工系規定系外課程需符合：

- 非進修部開設課程
- 非基礎概論性課程
- 課程內容與本系不重複或不相近
- 難度不低於本系課程

114 科目表畢業學分說明第 (6) 項另寫明：「修習進修部及大一概論性課程不認列，修習其他課程須先至系辦公室詢問是否計入畢業學分。」

系外專題課需確認與本系內容不同。**其他系所的規定尚未查證。**

### 已實作

`server/src/skills/outsideElective.js`。四個條件的可判定程度不同，處理強度也不同：

| 條件 | 可機械判定 | 處理 |
| --- | --- | --- |
| 非進修部開設 | 可（班級名稱含 `進修` 或學制為進修） | 不認列 |
| 內容不與本系重複 | 可（課名對必選修科目表） | 不認列 |
| 非基礎概論性 | 可（大一 **且** 課名含概論／導論／通論／概要／入門） | 不認列 |
| 難度不低於本系 | **不可** | 以課號級數為代理指標，**只警告不認列照舊** |

### 「不認列」不等於「不能修」

這組條件判定的是**能不能計入畢業學分**，不是能不能修這門課。因此不認列的處理要看
這門課是誰放進來的：

| 來源 | 處理 |
| --- | --- |
| 系統自己撿的候選（貪婪填充） | 整個剔除，不推薦不能認列的課；原因記入 `excludedCourses` |
| **使用者明確指定**（課程瀏覽器勾選、指定必選、重補修） | **保留並排入課表**，標記 `countsTowardGraduation: false`、`nonGraduationCategory: '系外選修未認列'`，並在警告中說明原因，由使用者自行決定去留 |

使用者明確指定的課若被靜默剔除，畫面上只會少一門課，沒有任何線索——而學生其實
可以修那門課，只是不計入畢業學分。這個決定必須交還給使用者。

「明確指定」的來源包含 `POST /api/schedule/generate` 的 `courseIds`（課程瀏覽器勾選的課，
它決定候選池但不會進入 `selectedCourseIds`）、`selectedCourseIds` 與
`mustTakeCourseIds`。不及格必修不屬於手動指定，必須由 `courseHistory` 自動推導。

「難度不低於本系課程」沒有任何可機械比較的欄位。把猜測當成硬性規則會靜默刪掉學生其實
可以修的課，比漏警告更糟，因此只發警告。

「概論性」也刻意要求**同時**滿足「大一」與「課名含概論字樣」：`人工智慧導論`、`資料探勘導論`
都是資工系三年級的核心選修／選修，只看課名會把難度相當的他系課程一併誤殺。

通過全部條件者一律標記 `needsOfficeConfirmation`，因為科目表明文寫「須先至系辦公室詢問」，
系統無權代替系辦認定。

**判定範圍**：只有「其他**系所班級**開的選修」才算系外選修。通識、共同科目、學院綜合班、
英語授課班、學分學程都不是系所班級，不屬於任何一系，不在此判定範圍——把它們當成系外選修
會讓通識課被這組條件過濾掉。

## 十、與 `docs/DEPARTMENT_MAPPING.md` 的名稱落差

官方必選修科目表的單位名稱與 A 表對照有三處不一致，會影響 `#13` 的系所比對：

| 官方名稱 | A 表名稱 | 說明 |
| --- | --- | --- |
| 建築學士學位學程 | 建築學系 | A 表簡稱 `建築` 對到「建築學系」 |
| 室內設計學士學位學程 | 室內設計進修學士班 | 官方有日間學士學位學程，A 表只有進修學士班 |
| 資訊電機學院學士班 | 資訊電機學院 | 名稱寫法不同 |

需與負責資料庫的組員確認 `User_Profiles.department` 實際會存哪一種寫法。
