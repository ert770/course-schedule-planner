## 學分要求

總畢業學分需求為 128 學分。

| 課程類別 | 學分數 |
| --- | ---: |
| 通識基礎 | 16 |
| 通識選修 | 12 |
| 必修 | 63 |
| 核心選修 | 12 |
| 選修 | 16 |
| 系外選修 | 9 |

特殊畢業門檻：資工系學生畢業前須修習 2-6 學分數位課程。

## 課程狀態

### 關注

`關注` 課程會顯示在課表上，供學生觀察時間分佈。

規則：

- 可同時關注多門同時段課程。
- 不計入正式排課衝突。
- 用於比較、預覽與決策。

### 加選

`加選` 課程會顯示在課表上，且正式佔用該時段。

規則：

- 同時間不可加選多門課。
- 若多門加選課程時段重疊，視為衝堂。
- 排課演算法產生正式課表時，應以加選狀態判斷衝堂。

## 大二以上排課流程

1. 讀取學生過去修習紀錄與歷史成績。
2. 推估當學期應補足的課程類別與學分。
3. 優先安排必修課。
4. 若學生曾有必修課不及格，檢查當學期是否開授重補修課程，並優先排入。
5. 必修確定後，依序安排核心選修、一般選修、通識、系外選修。
6. 依照偏好產生多個課表方案。
7. 回傳課表、學分、衝堂資訊、推薦理由與備選課程。

## 核心選修與選修路徑

核心選修與選修主要支援三條修課路徑：

- 嵌入式系統類。
- 技術應用類。
- 網路安全類。

規則：

- 依照學生偏好路徑與預定修習學分，優先排入核心選修。
- 核心選修不足時，再補入一般選修。
- 技術應用類核心選修剛好 12 學分。
- 其他類別可能缺 1 或 3 學分，需允許跨類別核心選修補齊。
- 學生可不完全按照三條路徑修課，系統需支援客製化偏好。

## 推薦因素

選修推薦需考慮：

- 學生興趣。
- 教授容易度。
- 課程難易度。
- 給分甜度。
- 評價推薦分數。
- 是否可集中排課。
- 是否能空出休息日。

通識與系外選修推薦需考慮：

- 是否符合興趣。
- 是否容易取得高分，例如 95 分以上。
- 是否為涼課。
- 是否免考試，只需報告。

## 硬性限制

硬性限制違反時，課表方案不得成立：

- 加選課程不得衝堂。
- 必修與重補修優先。
- 總學分不得超過上限。
- 若指定必修課無法排入，必須回傳失敗原因。
- 被封鎖時段不得排入正式加選課程。

## 軟性偏好

軟性偏好可用於排序不同課表方案：

- 不上早八。
- 不上晚課。
- 週一空堂或空出指定整天。
- 午休保留。
- 集中排課。
- 免期中考。
- 免分組報告。
- 偏好討論課。
- 偏好英文授課。
- 偏好學到較多內容。

## 衝堂判定

兩門加選課程若符合以下條件，即為衝堂：

- `dayOfWeek` 相同。
- 其中一門課的時段與另一門課的時段重疊。

判定公式：

```text
not (courseA.endPeriod < courseB.startPeriod or courseB.endPeriod < courseA.startPeriod)
```

## 多方案課表

系統不應只產生一份課表。至少應支援：

- 學分最大化方案。
- 集中排課方案。
- 興趣優先方案。
- 涼課/高分優先方案。
- 必修與重補修優先方案。

每個方案應包含：

- 課程清單。
- 總學分。
- 方案類型。
- 推薦理由。
- 被排除課程與原因。
