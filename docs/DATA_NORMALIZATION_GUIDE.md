# 資料正規化對照表（爬蟲端 ↔ 後端）

日期：2026-10-05
對象：產生或寫入 `User_Profiles`、`User_Course_History`、`User_Course_States` 的組員。
依據：2026-10-05 對資料庫的唯讀稽核（`docs/DB_AUDIT_REPORT_2026-10-05.md`）與後端程式實際讀取的方式。

## 0. 一句話原則

**寫入前統一成一種寫法，不要讓後端去猜。** 後端對每個欄位只認一種寫法；寫成別的不會報錯，
而是被靜默當成「沒有資料」——偏好不生效、已修課不排除、畢業學分算錯，而且畫面上看不出原因。

所有「標準值」都以 **D1249697（user_id 1）目前的寫法**為準，那是後端唯一完整支援的一種。

## 1. 先認清楚：同一個東西有好幾種編號

寫錯編號是最常見的錯。先對照這兩張表。

### 課程的四種編號

| 編號 | 範例 | 來源欄位 | 什麼時候用 |
| --- | --- | --- | --- |
| **課號** | `IECS3002` | `Courses.subid3` | 修課紀錄的 `catalog_course_code`。一門課一個，跟哪一班無關 |
| **班次 ID** | `1291` | `Course_Sections.section_id` | 指定必修、關注清單、已存課表。指「某老師某時段的那一班」 |
| 選課代號 | `1306` | `Course_Sections.selection_code` | 只有評價資料在用。**不要**拿來填使用者資料 |
| 課程內部鍵 | `AS00100-00739` | `Courses.course_id` | 只用於資料表之間的關聯。**不要**拿來填使用者資料 |

同一門「人工智慧導論」的實際資料：

| 課號 | 班次 ID | 選課代號 | 班級 | 教師 |
| --- | ---: | --- | --- | --- |
| `IECS3059` | 1291 | 1306 | 資訊三合 | 林哲維 |
| `IECS3059` | 1292 | 1307 | 資訊三合 | 林峰正 |
| `IECS3059` | 1293 | 1308 | 資訊三合 | 張哲誠 |

「修過人工智慧導論」→ 填課號 `IECS3059`。「想加選林哲維那一班」→ 填班次 ID `1291`。

### 使用者的三種編號

| 編號 | 範例 | 用在哪裡 |
| --- | --- | --- |
| 學號 | `D1249697` | 登入、帳號清單 |
| `user_id` | `1`、`9001` | `User_Profiles`、`User_Course_History`、`User_Course_States`、`Saved_Schedules` |
| `subject_id` | `v1:d256f4…` | 互動事件、同意紀錄、學習權重。由系統算出，**不要自己填** |

三者靠後端的**帳號清單**互相對應。只寫 `User_Profiles` 而沒有登記在帳號清單的使用者，
系統會回「使用者不存在」。

## 2. `User_Course_History`（修課紀錄）

每修一次課一筆。重修就有兩筆（同課號、不同學期）。

| 欄位 | 標準寫法 | 不要這樣寫 | 說明 |
| --- | --- | --- | --- |
| `user_id` | 整數，如 `9001` | | 必須已存在於 `User_Profiles` |
| `catalog_course_code` | **真實課號**，如 `IECS1006` | `IECS102`、`MATH101` | 必須查得到：`SELECT 1 FROM Courses WHERE subid3 = ?`，或已存在於其他人的修課紀錄 |
| `course_name` | 與真實課程**完全相同** | 自行簡化或改寫 | 系統會用課名判斷是否為系必修，例如 `程式設計(I)` 不能寫成 `程式設計(一)` |
| `academic_year` | 民國學年，如 `113` | 西元年 | 見第 6 節的學年對照 |
| `semester` | `1`（上）或 `2`（下） | `上學期`、`first` | 這張表用數字 |
| `credits` | 與真實課程相同，如 `2.0` | 自己估的學分 | |
| `score` | 0～100，如 `76.00` | 空值 | 用來挑探索頁的預設起點 |
| `letter_grade` | `A+`、`B`、`F`…，或 `NULL` | | 可空 |
| `passed` | `1`（60 分以上）或 `0` | | 被當的課照寫，`passed = 0` |
| `requirement_type` | `必修`、`選修`、`通識` | `專業必修`、`required` | 這欄用中文 |
| `graduation_category` | `required`、`elective`、`general`、`external`、`nonGraduation` | `專業必修`、`共同必修`、`專業選修`、`通識` | **這欄用英文代碼**，判定方式見 2.1 |
| `general_education_category` | 通識課填領域，其餘 `NULL` | | 寫法待決定，見第 9 節 |
| `source` | 來源標記，如 `mock_persona` | 空值 | 用來區分真實資料與合成資料，務必保留 |

**不要寫入當前學期（114 下）的課。** 修課紀錄是「已經修完」的課。把本學期的課寫進去，
系統會把它當成已通過，再替同一個學期排課。

### 2.1 `graduation_category` 怎麼判定

這欄的意思是「**這門課對這位學生而言，算哪一類畢業學分**」。它不等於 `Courses.category`
（那是「對開課系所而言是什麼」）。同一門課對不同系的學生可能不同，所以**不能直接照抄
`Courses.category`，也不能只把中文翻成英文**。

以資訊工程學系的學生為例，依下表由上往下判定，命中就停：

| 順序 | 課的種類 | 例子 | `graduation_category` | `requirement_type` |
| ---: | --- | --- | --- | --- |
| 1 | 體育、國防、班級活動、服務學習 | 體育(一)、國防科技、班級活動 | `nonGraduation` | 必修 |
| 2 | 通識基礎必修 | 中文思辨與表達、大學基礎／精進英文、現代公民與社會實踐、科學與人文的對話 | `general` | 必修 |
| 3 | 系必修（必選修科目表的 63 學分） | 程式設計(I)～(IV)、資料結構、微積分(一)(二)、線性代數、邏輯設計、普通物理 | `required` | 必修 |
| 4 | 本系選修（課號 `IECS` 開頭、不在必修清單） | 人工智慧導論、程式語言、Web程式設計 | `elective` | 選修 |
| 5 | 通識選修（通識領域開的課） | 生態環境保育、奈米科技與生活 | `general` | 選修 |
| 6 | 其他系開的選修 | 西班牙文(一)、投資學 | `external` | 選修 |
| 7 | 以上都判不出來 | | `unspecified` | 未確認 |

容易判錯的三種：

- **「共同必修」不是一類。** 中文與英文是通識（`general`）；體育與班級活動不計入畢業
  （`nonGraduation`）；微積分、物理是系必修（`required`）。
- **微積分、線性代數、邏輯設計、普通物理由外系開課**，課號不是 `IECS`
  （`MATH1005`、`IEE1005`、`IEE1006`、`IEE1010`），但對資工學生是 `required`。
- **國防科技**是 `nonGraduation`，不是選修。

系必修清單在 `server/src/data/csCurriculum.js` 的 `REQUIRED_COURSES`。
後端已有現成的判定函式 `classifyHistoryEntryByCurriculum()`
（`server/src/data/courseHistoryClassification.js`），涵蓋第 2～4 類。

## 3. `User_Profiles`（使用者主檔）

每位使用者一筆。

| 欄位 | 標準寫法 | 不要這樣寫 | 說明 |
| --- | --- | --- | --- |
| `user_id` | 整數 | | persona 用 9001～9010 |
| `name` | 姓名 | | |
| `department` | `資訊工程學系` | `'資訊工程學系'`（含引號）、`資工系` | 系所全名，不含引號 |
| `class_name` | `資訊二乙` | `資工二乙`、`2B` | 必須是課程資料裡實際存在的班級；見 3.2 |
| `grade_level` | `1`～`4` | | 延畢填 `4` |
| `admission_year` | 見第 6 節 | 以 113 為當前學年去算 | |
| `program_type` | `bachelor` | `日間學士班`、`major` | 碩士 `master`、博士 `doctoral` |
| `college` | `資訊電機學院` | | |
| `max_credits` | 不超過 `25` | `28` | 校規上限 25，超過會被後端擋下 |
| `preference_tags` | **帶 `#` 的固定標籤**陣列 | `["不排早八"]`、`["noMorningClasses"]` | 見 3.1 |
| `avoid_time` | `[{"day":1,"period":1}]` | `["08:00"]` | `day` 1～7（週一＝1），`period` 1～14 |
| `avoid_instructors` | **真實教師姓名**陣列 | `["地雷教師A"]` | 必須與 `Course_Sections.teacher` 完全相同才會生效 |
| `must_take_courses` | **班次 ID** 陣列，如 `[1291]`；沒有就 `[]` | `["MATH101"]`、`["0123"]` | 被當的必修**不用填**，後端會依修課紀錄自動安排重補修 |
| `watchlist` | **班次 ID** 陣列；沒有就 `[]` | 課號、選課代號 | |
| `enrolled_programs` | 學程名稱陣列；沒有就 `[]` | `["資工系學士班"]` | 主修不是學程 |
| `completed_courses` | `[]` | 填課號 | 後端不讀這欄，已修課以修課紀錄為準；填了只會兩邊不一致 |
| `preferences_json` | `NULL`，或下方的結構 | 自訂結構 | 興趣主題存在這裡 |
| `password_hash` | `NULL` | bcrypt 雜湊 | **登入不讀這欄**，見第 5 節 |

`preferences_json` 的結構（要讓「興趣導向方案」排得出來才需要）：

```json
{ "schemaVersion": 1,
  "values": { "interests": ["機器學習", "Python"], "preferredTrack": "技術應用類", "preferredKeywords": [] } }
```

`preferredTrack` 只能是 `嵌入式系統類`、`技術應用類`、`網路與安全類` 或 `null`。

| `#期末報告為主` | | `finalReport` | 期末專案產出 |
| `#平時成績佔比高` | | `weightDaily` | 平時成績佔比高 |

**沒有對應標籤的**（後端目前沒有這些偏好，寫了不會生效）：

| 目前 persona 寫的 | 人設的英文代碼 | 怎麼處理 |
| --- | --- | --- |

### 3.2 班級名稱

格式是「系所簡稱＋年級＋班別」，例如 `資訊一甲`、`資訊二乙`、`資訊三合`。

本學期（114 下）資工系大學部實際有開課的班級：

| 年級 | 班級 |
| --- | --- |
| 一 | 資訊一甲、資訊一乙、資訊一丙、資訊一合 |
| 二 | 資訊二甲、資訊二乙、資訊二丙、資訊二丁、資訊二合 |
| 三 | 資訊三甲、資訊三乙、資訊三丙、資訊三丁、資訊三合 |
| 四 | **只有資訊四合** |

「合」是該年級各班共同修習的合班，不是學生的班別；一到三年級的學生請填甲～丁。`資訊四甲`、`資訊四乙`、`資訊四延` 在課程資料裡沒有任何班次，
填這些班級的學生不會有「本班必修」可排。四年級與延畢生建議填 `資訊四合`。

## 5. 帳號與同意紀錄（規格書沒寫，但缺了就不能用）

**帳號清單。** 後端用它把學號、`user_id` 互相對應，登入也是比對這裡的學號與密碼。
不在清單裡的 `user_id`，登入、排課、探索都會回「使用者不存在」。

- 要讓 persona 被系統認得：請後端把 `user_id` 加進帳號清單。
- 要讓 persona 能登入：還需要一組學號與密碼，一樣放在帳號清單。`User_Profiles.password_hash`
  目前不會被讀取。

**同意紀錄。** 新帳號第一次使用會被導到同意頁。腳本要直接替 persona 排課的話，
需要後端先替它們寫入同意紀錄（服務處理；要參與偏好學習另需個人化學習）。
這張表的 `subject_id` 由後端計算，**請不要自己寫入**。

## 7. 四個完整例子

### 例一：一筆系必修（課號、學分、分類都要改）

寫入前：

```json
{ "user_id": 9001, "catalog_course_code": "IECS102", "course_name": "程式設計(I)",
  "academic_year": 114, "semester": 1, "credits": 1.0, "score": 82.0, "letter_grade": "A-",
  "passed": 1, "requirement_type": "必修", "general_education_category": null,
  "graduation_category": "專業必修", "source": "mock_persona" }
```

正規化後：

```json
{ "user_id": 9001, "catalog_course_code": "IECS1006", "course_name": "程式設計(I)",
  "academic_year": 114, "semester": 1, "credits": 2.0, "score": 82.0, "letter_grade": "A-",
  "passed": 1, "requirement_type": "必修", "general_education_category": null,
  "graduation_category": "required", "source": "mock_persona" }
```

改了三處：課號 `IECS102` → `IECS1006`；學分 1 → 2（真實課程是 2 學分）；
分類 `專業必修` → `required`。

### 例二：體育與國防（不計入畢業學分）

寫入前：

```json
[ { "catalog_course_code": "PE101", "course_name": "體育(一)", "credits": 1.0,
    "requirement_type": "必修", "graduation_category": "共同必修" },
  { "catalog_course_code": "MILI101", "course_name": "國防科技", "credits": 1.0,
    "requirement_type": "選修", "graduation_category": "專業選修" } ]
```

正規化後：

```json
[ { "catalog_course_code": "ATHL1003", "course_name": "體育(一)", "credits": 1.0,
    "requirement_type": "必修", "graduation_category": "nonGraduation" },
  { "catalog_course_code": "MILT1035", "course_name": "國防科技", "credits": 1.0,
    "requirement_type": "必修", "graduation_category": "nonGraduation" } ]
```

重點：這兩門**不能**翻成 `required` 或 `elective`。照字面翻譯的話，每位學生會多算
4～6 個不該計入的畢業學分。

### 例三：通識基礎必修（不是通識選修）

寫入前：

```json
{ "catalog_course_code": "GE001", "course_name": "科學與人文的對話", "credits": 2.0,
  "requirement_type": "通識", "general_education_category": "自然",
  "graduation_category": "通識" }
```

正規化後：

```json
{ "catalog_course_code": "GEK2000", "course_name": "科學與人文的對話", "credits": 2.0,
  "requirement_type": "必修", "general_education_category": null,
  "graduation_category": "general" }
```

重點：「科學與人文的對話」與「現代公民與社會實踐」是通識的**核心必修**，不屬於任何領域。
`requirement_type` 是 `必修`，`general_education_category` 是 `NULL`。中文思辨與大學英文同理。
通識**選修**才填領域。

### 例四：一整筆使用者主檔（林子軒，9001）

寫入前：

```json
{ "user_id": 9001, "name": "林子軒", "department": "資訊工程學系", "class_name": "資訊一甲",
  "grade_level": 1, "admission_year": 113, "max_credits": 25,
```
