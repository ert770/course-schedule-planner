# 系統需求規格

## 目標

本系統協助資工系學生依照畢業學分要求、歷史修課紀錄、個人偏好、課程時間與課程評價，產生可比較的推薦課表。

## 使用者

主要使用者：

- 資工系大二以上學生。
- 需要規劃當學期課表的學生。
- 需要補修、重修或檢查畢業學分缺口的學生。

次要使用者：

- 專題展示評審。
- 系統開發者與維護者。

## 核心問題

學生排課時常同時面臨：

- 必修、重補修、核心選修、選修、通識、系外選修的學分要求。
- 課程衝堂。
- 想集中排課或空出休息日。
- 想選高分課、涼課、免考試或符合興趣的課。
- 核心選修路徑不一定剛好滿足學分，需要跨類別補足。
- 單一推薦課表不一定符合學生主觀偏好，因此需要多方案比較。

## MVP 功能範圍

MVP 必須提供：

- 使用者登入。
- 初始偏好設定。
- 課程搜尋。
- 課程關注與加選狀態。
- 依條件產生推薦課表。
- 顯示衝堂或學分不足問題。
- 顯示畢業學分進度。
- AI Agent 問答與工具呼叫。
- 課表儲存。

## 排課需求

系統需支援：

- 總畢業學分 128。
- 通識基礎 16 學分。
- 通識選修 12 學分。
- 必修 63 學分。
- 核心選修 12 學分。
- 選修 16 學分。
- 系外選修 9 學分。
- 數位課程 2-6 學分特殊畢業門檻。
- 大二以上學生以歷史修課紀錄推估當學期課程需求。
- 必修與重補修優先排入。
- 核心選修、一般選修、通識、系外選修依序補足。
- 多個課表方案。

## AI Agent 需求

Agent 必須能：

- 解釋推薦結果。
- 查詢課程。
- 查詢課程評價。
- 根據使用者自然語言更新偏好。
- 呼叫排課工具產生課表。
- 在資料不足時明確說明限制。

Agent 不得：

- 編造不存在的課程。
- 編造教師、學分、評價或畢業門檻。
- 直接把 LLM 生成結果當作事實資料。

## 非功能需求

- 前端應可透過 `npm run build` 建置。
- 後端 API 預設運行於 port `3001`。
- 本地資料目前使用 JSON 檔案式資料庫。
- API key 必須透過 `.env` 設定，不可提交到 Git。
- 規格文件應隨 API、資料格式與排課邏輯同步更新。

## 不做範圍

目前不做：

- 正式校務系統整合。
- 真實 Dcard/外部論壇爬蟲。
- 多人同時寫入資料保證。
- 正式資料庫部署。
- 自動選課送出到學校系統。
- 以 LLM 完全取代排課演算法。
